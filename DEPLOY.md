# Frequency Atlas — онлайн-розгортання (підготовлено 24.09.2026)

## Що вже виконано

У Supabase створено проєкт **Frequency Atlas** в організації **RomanDeboi's Org**, регіон `eu-central-1`. Застосовано `supabase/cloud_v0_3.sql`: таблицю `atlas_vaults`, функцію `save_atlas_vault` із контролем ревізій, приватний bucket `atlas-screenshots` та політики RLS. Перевірено, що для `anon` відсутні права на читання таблиці та виклик функції, bucket не є публічним, а перевірка Supabase Security Advisor не повернула зауважень. База поки порожня; локальні дані не переносилися.

**Це не означає, що вебсайт уже розгорнуто.** В акаунтах поки немає репозиторію GitHub і проєкту Vercel. Дії нижче виконуються власником, після чого можна перевірити сайт.

## 1. Створи приватний GitHub-репозиторій

Відкрий <https://github.com/new>, обери акаунт `RomanDeboi`, назви репозиторій `frequency-atlas` і встанови **Private**. Залиш ініціалізацію з README, `.gitignore` і license вимкненою — вони вже є в проєкті. Не завантажуй у GitHub файли `.env.local`, токени, паролі чи дані, яким заборонене зберігання в публічних хмарних сервісах.

Розпакуй цей архів на ПК, відкрий термінал у папці `frequency-atlas-v0.3` і виконай:

```bash
git init -b main
git add .
git commit -m "Frequency Atlas v0.3 cloud"
git remote add origin https://github.com/RomanDeboi/frequency-atlas.git
git push -u origin main
```

GitHub може попросити авторизуватися; для HTTPS Git-пароль акаунта не використовується — потрібен Git Credential Manager, GitHub CLI або дозволений токен. Не вставляй токени в чат.

## 2. Імпортуй репозиторій у Vercel

Відкрий <https://vercel.com/new> → **Import Git Repository** → `RomanDeboi/frequency-atlas`, за потреби дозволь Vercel доступ саме до цього приватного репозиторію. Framework preset — **Next.js**, Root Directory — `/` (корінь репозиторію). Обери безкоштовний **Hobby** для особистого некомерційного проєкту.

**До натискання Deploy** додай в Environment Variables (Production, а якщо використовуватимеш прев'ю — також Preview):

| Назва | Значення |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://vidahhuiroselvxadglo.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Активний ключ `sb_publishable_…` із Supabase → Settings → API Keys |
| `NEXT_PUBLIC_ATLAS_ALLOW_SIGNUP` | `true` лише до реєстрації твого власного акаунта |

**Ніколи не додавай `service_role` або `sb_secret_` ключ у змінні `NEXT_PUBLIC_*`.** Потрібний тільки *publishable* ключ, він створений саме для браузерних клієнтів. Файлу `.env.local` в репозиторії бути не повинно.

Натисни **Deploy**. Після успішного розгортання запиши фактичну HTTPS-адресу, яку видав Vercel. Її неможливо визначити наперед; вигадану адресу не використовуй для Auth.

## 3. Налаштуй Auth для фактичного домену

Відкрий <https://supabase.com/dashboard/project/vidahhuiroselvxadglo/auth/url-configuration>.

- **Site URL** → фактична production-адреса Vercel, наприклад `https://<твій-домен>.vercel.app`.
- **Redirect URLs** → додай `https://<твій-домен>.vercel.app/cloud` та за потреби точні preview-домени, якщо тестуватимеш Auth на них.
- Переконайся, що Email Auth і підтвердження email налаштовані відповідно до твоїх вимог.

Тоді відкрий `https://<твій-домен>.vercel.app/cloud`, створи власний акаунт, підтвердь email і увійди. Після реєстрації заборони нові реєстрації у **Supabase Authentication → Providers → Email**, зміни `NEXT_PUBLIC_ATLAS_ALLOW_SIGNUP=false` у Vercel та ініціюй нове розгортання. Прихована кнопка в інтерфейсі сама по собі не забороняє реєстрацію; важлива саме серверна настройка Supabase.

Для особистого користування бажано ввімкнути MFA на облікових записах Supabase, GitHub і Vercel.

## 4. Перевір збереження й синхронізацію

У `/cloud` створи тестовий нешкідливий запис із діапазоном, прикріпи невеликий PNG, збережи, онови сторінку й перевір на іншому пристрої. Переконайся, що без входу інформація не відображається, а скриншот не має публічного URL. Для регулярної резервної копії використай **Експорт JSON**. Імпорт JSON **замінює всю хмарну базу**, тому спочатку зроби експорт, якщо записи там уже є.

## Важливі обмеження

- v0.3 зберігає метадані акаунта **в одному JSONB-документі** `atlas_vaults`; це не нормалізовані таблиці технологій/діапазонів/спостережень. Така схема відповідає поточному `cloudAdapter.ts` і працює з уже створеною міграцією. Нормалізацію можна виконати в наступному релізі після перевірки перенесення даних.
- Сховище `atlas-screenshots` є приватним, але підписані посилання на зображення тимчасово відкривають файл для будь-кого, кому передано чинне посилання. Не пересилай ці посилання.
- Без дозволу та належного режиму захисту **не завантажуй службові, конфіденційні або оперативні відомості** в звичайну хмару. Цей проєкт не проходив спеціалізованої сертифікації безпеки.
- `prototype.html` — окрема локальна демонстраційна база в браузері. Хмарні записи з `/cloud` автоматично в неї не копіюються.
- Наразі веброзгортання та live-тест входу не проведені. Програмні модульні тести проходили; браузерний smoke-тест у робочому середовищі блокувався мережевими правилами тестового браузера.
